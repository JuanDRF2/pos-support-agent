# Proposal — POS support chat agent with RAG and evals

## Intent
Merchants with a POS question (partial refund, renew a subscription, gift a renewal) depend on
searching docs or waiting for human support, which is slow and inconsistent between agents.
This initiative builds a **portfolio demo** that shows a single-turn support chat answering
those questions from three help articles, with **real RAG and real, deterministic evals**.
It is not for real merchants: no auth, no real customer data, everything synthetic and local.

## Scope
- In:
  - Three synthetic Markdown help articles (`pos-checkout.md`, `pos-renewals.md`, `gift-renewal-pos.md`), written by Juan.
  - Local ingestion: chunk by heading, embed locally, save a JSON index.
  - Single-turn chat: retrieve, refuse in code when evidence is weak, otherwise generate with Ollama.
  - A simple chat web page served on localhost.
  - A golden set (written after the docs) and an eval suite with a 3-category scorecard: retrieval, faithfulness, correct refusal.
- Out (no-gos):
  - Login/authentication, real actions on a POS, production deploy, persistent history, real payment integrations.
  - Multi-turn memory, any hosted service, any paid or key-gated API.
  - Any real customer or employer content in the knowledge base.

## Approach
Lane A (single system, small scope, all local). Pieces:
1. **Knowledge base**: 3 articles in `docs/kb/`, each procedure under its own `##` heading.
2. **Ingest**: chunk by heading (numbered steps stay together) → local embeddings → `data/index.json`.
3. **Retrieve**: embed the question locally, cosine top-k over the in-memory index.
4. **Answer (single turn)**: if the top score is below a calibrated threshold, return the canned refusal and never call the model. Otherwise call Ollama with a strict "answer only from context" prompt; if it replies `NOT_IN_DOCS`, return the refusal. The result is a discriminated union `ChatResult` (`answer` | `refusal`).
5. **Server + page**: Node built-in `http` bound to `127.0.0.1`, one static `index.html`, one `POST /api/chat`.
6. **Evals**: run the golden set through the same `answer()` function; all three categories are deterministic.
7. **Screen** (design gate skipped by the person's decision; described in text instead): one centred column titled "POS Support", scrolling message area, input box and Send button at the bottom. User messages right-aligned, agent replies left-aligned with a `Source: <file>.md` line. Refusals use the same bubble style. A "thinking..." state while waiting. If Ollama is down, a plain error message. No history; reload clears the page.

### Deterministic faithfulness checks (v1)
1. The answer cites the correct source document.
2. It contains the key phrases/facts listed for that question in the golden set.
3. Every number, amount, time period and named option in the answer also appears in the retrieved chunks (catches the most common invention).

**Honest limitation (to be stated in the README):** these checks are a proxy. They catch missing
or invented specifics; they do not understand meaning, so a fluent but subtly wrong sentence
without new numbers or names could pass. The scorecard never shows a fake percentage.

## Risks & mitigations
- **Ollama not installed / not running; 7-8B model is a ~4-5 GB download** → setup steps in the README, a startup check with a plain message, model name configurable, documented as a prerequisite (not infrastructure: local, no cost, nothing shared).
- **Trap questions leak past the threshold** (e.g. "how do I refund a gift card?" shares vocabulary with real docs) → threshold **plus** `NOT_IN_DOCS`; golden set includes near-miss unanswerable questions; threshold calibrated on the golden set, with about 5 held-out questions to avoid overfitting. With ~20 questions percentages are coarse; the README says so.
- **`npm test` fragile on a fresh machine** (needs Ollama for questions that pass the threshold, plus a first-run model download) → fail loudly with clear messages; `eval:fast` and `test:unit` need no LLM; `genesis verify` runs only the fast tier.
- **Ollama output is not fully deterministic** → temperature 0 and a fixed seed; the README states that small variance is possible.
- **Golden-set circularity** (questions derived from the docs can be too easy) → include paraphrases that don't reuse the docs' wording, plus traps.
- **Chunking splits a procedure** → chunk by heading, one procedure per heading, a unit test asserting no chunk ends mid-numbered-list.
- **Model download offline** (about 25 MB embeddings, first run only, HTTPS, TLS verification on) → clear error, cached under `.cache/`.
- **Prompt injection / XSS** → no tools or actions in the chat, so the worst case is a wrong answer; question and context in separate delimited prompt sections; page renders with `textContent`, never `innerHTML`.
- **Local exposure** → server binds to `127.0.0.1` only; body size cap (10 KB, 413) and input length cap (~500 characters).
- **Ollama over plain HTTP** → localhost only, a documented exception to "HTTPS only"; the base URL is validated as local or a warning is logged.
- **Logging** → counts, scores and timings only; not the question text.
- **New dependency weight** (`onnxruntime-node`, native binaries) → verify on this machine as the first task; run `npm audit` before closing.
- **If the person later wants it hosted or shared** → that becomes Lane B and needs a new initiative.

## Rollback
Everything is new and local. Rollback is reverting the commits of this initiative, deleting `data/` and `.cache/`, and restoring the earlier `AGENTS.md` and `package.json` text from git history.

## Success criteria
- Given the index is built, when I ask "how do I process a partial refund?", then the answer gives the correct step and cites `pos-checkout.md`.
- Given the same setup, when I ask "how do I reset my POS password?", then it says it doesn't know and suggests contacting support, without inventing steps.
- When I run `npm test`, then it prints a scorecard with a percentage for retrieval, faithfulness and correct refusal, all computed deterministically; a category that could not run shows SKIPPED, never a made-up number.
- Embeddings are generated locally and answers by Ollama; no external API key of any kind is needed.
